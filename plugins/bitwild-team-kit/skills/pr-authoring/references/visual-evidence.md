# Visual evidence

Use a real rendered screenshot for a visible layout change and a short recording when motion or a sequence explains behavior. Capture only the relevant surface, state and viewport; avoid exposing unrelated private information. Prefer before/after when that comparison helps. Use useful alt text and short captions. Supplied captures can be used with truthful attribution.

When the environment permits, inspect the affected UI through the available browser or native tools. If it cannot run, describe the missing check rather than claiming visual verification.

Use genuine uploaded attachment URLs in a GitHub body. A local file path is not a remote attachment. Upload through an authorized supported surface; if upload is unavailable, retain the local artifact, report its path to the user outside the PR body, and use a clear media-pending placeholder. Do not fabricate URLs or mark evidence complete. Preserve draft status when required evidence is missing.
